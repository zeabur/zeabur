# Build

Zeabur menggunakan [zbpack](https://github.com/zeabur/zbpack) sebagai alat internal untuk melakukan build layanan pengguna, sehingga pengguna dapat men-deploy layanan berbasis bahasa dan framework apa pun dengan satu klik tanpa perlu memahami detail yang rumit.

Saat ini, [zbpack]((https://github.com/zeabur/zbpack)) telah mendukung semua bahasa pemrograman utama untuk pengembangan web, serta melakukan identifikasi dan optimasi lebih lanjut untuk setiap framework populer. Selain itu, zbpack juga terus diperbarui untuk mendukung bahasa pemrograman dan framework baru:

- Node.js
- Python
- PHP
- Ruby
- Go
- Java
- .NET
- Rust
- Elixir

Jika bahasa atau framework yang digunakan layanan Anda tidak ada dalam daftar di atas, atau jika Anda menemukan masalah pada zbpack selama proses build, silakan kontribusikan Pull Request di [GitHub](https://github.com/zeabur/zbpack/pulls) untuk membantu kami meningkatkan fungsionalitas zbpack.

Saat Anda menggunakan zbpack untuk melakukan build layanan dalam sebuah proyek, zbpack akan secara otomatis mengidentifikasi bahasa dan framework yang digunakan layanan berdasarkan kode, file konfigurasi, dan informasi lain dalam proyek, lalu memilih cara build yang sesuai berdasarkan informasi tersebut.

## Membuat Build Plan

Sebagai contoh, misalkan Anda telah mengembangkan aplikasi web berbasis [Next.js](https://nextjs.org/):

```bash
git clone https://github.com/zeabur/nextjs-template
cd nextjs-template
```

Saat Anda menjalankan perintah `zbpack` di folder proyek ini, Anda dapat melihat build plan yang disesuaikan untuk proyek tersebut:

```bash
zbpack .

╔══════════════════════════════ Build Plan ═════════════════════════════╗
║ provider         │ nodejs                                             ║
║───────────────────────────────────────────────────────────────────────║
║ nodeVersion      │ 18                                                 ║
║───────────────────────────────────────────────────────────────────────║
║ installCmd       │ pnpm install                                       ║
║───────────────────────────────────────────────────────────────────────║
║ buildCmd         │ pnpm run build                                     ║
║───────────────────────────────────────────────────────────────────────║
║ startCmd         │ pnpm start                                         ║
║───────────────────────────────────────────────────────────────────────║
║ packageManager   │ pnpm                                               ║
║───────────────────────────────────────────────────────────────────────║
║ framework        │ next.js                                            ║
╚═══════════════════════════════════════════════════════════════════════╝
```

Dari gambar di atas, terlihat bahwa `zbpack` memilih Provider `nodejs` sebagai penyedia solusi untuk build, yang berarti dalam rencana selanjutnya zbpack akan melakukan hal-hal berikut:

1. Mencari tahu versi Node.js yang digunakan layanan
2. Mencari tahu package manager yang digunakan layanan, apakah `npm`, `yarn`, atau `pnpm`
3. Mencari tahu perintah yang digunakan layanan untuk menginstal dependensi
4. Mencari tahu perintah yang digunakan layanan untuk build
5. Mencari tahu perintah yang digunakan layanan untuk start
6. Mencari tahu framework Node.js yang digunakan layanan
