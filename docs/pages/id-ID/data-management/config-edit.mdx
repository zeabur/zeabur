# Editor Konfigurasi

Saat menjalankan layanan, Anda dapat menyesuaikan berbagai pengaturan melalui file konfigurasi. Zeabur menyediakan editor file konfigurasi yang memungkinkan Anda menentukan lokasi penyimpanan dan isi file konfigurasi melalui editor. File konfigurasi akan dipasang secara otomatis saat layanan dimulai.

Di sini kami menggunakan [NGINX](https://nginx.com/) sebagai reverse proxy untuk layanan internal [vaultwarden](https://github.com/dani-garcia/vaultwarden), untuk mendemonstrasikan proses penggunaan editor file konfigurasi dalam mengubah file konfigurasi NGINX.

## Langkah 1: Buat Proyek

Buat sebuah proyek di [Dashboard Zeabur](https://zeabur.com/).

## Langkah 2: Buat Layanan

Buat Prebuilt Service untuk NGINX dan Vaultwarden di proyek tersebut.

![Create NGINX Service](/data-management/config-edit/create-nginx-service.en-US.png)

![Create Vaultwarden Service](/data-management/config-edit/create-vultwarden-service.en-US.png)

## Langkah 3: Edit File Konfigurasi Layanan NGINX

1. Di bagian layanan, klik tombol dropdown pada blok `Pengaturan` layanan NGINX, cari bagian `Konfigurasi`, lalu klik tombol `Buka Editor Konfigurasi` untuk masuk ke editor file konfigurasi.

![Open Config Editor](/data-management/config-edit/open-config-editor.en-US.png)

2. Di editor yang terbuka, klik tombol `Tambah File Konfigurasi` untuk menambahkan file konfigurasi baru. Pada kolom input `Config Path` di formulir pop-up, masukkan path dan nama file konfigurasi. Di sini kami memasukkan `/etc/nginx/nginx.conf`, lalu klik tombol `Save Config`.

![Add Config File](/data-management/config-edit/create-new-config.en-US.png)

<Callout>
    `Config Path` di atas harus berupa path absolut dari file konfigurasi. Silakan sesuaikan dengan kondisi Anda.
</Callout>

3. Edit isi file konfigurasi sesuai kebutuhan. Di sini kami menambahkan blok `server` untuk melakukan reverse proxy ke layanan Vaultwarden.

```nginx
worker_processes  4;
error_log  stderr;
worker_rlimit_nofile 8192;

events {}

http {
  default_type application/octet-stream;
  log_format   main '$remote_addr - $remote_user [$time_local]  $status '
    '"$request" $body_bytes_sent "$http_referer" '
    '"$http_user_agent" "$http_x_forwarded_for"';
  access_log   /dev/stdout  main;
  sendfile     on;
  tcp_nopush   on;
  server_names_hash_bucket_size 128; # this seems to be required for some vhosts

  map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      "";
  }

  server {
    listen 80 default_server;
    server_name _;

    location / {
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection $connection_upgrade;

      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;

      proxy_pass http://vaultwarden.zeabur.internal:80;
    }
  }
}
```

Agar orang lain dapat mengakses layanan internal Vaultwarden melalui layanan NGINX, kami menggunakan direktif `proxy_pass http://vaultwarden.zeabur.internal:80;` di NGINX, yang berarti NGINX akan meneruskan semua permintaan ke lokasi ini menuju Vaultwarden. Kami menggunakan fitur [jaringan privat](/deploy/networking/private-networking) untuk mengakses Vaultwarden di dalam jaringan privat menggunakan hostname yang tetap.

4. Klik tombol `Simpan` untuk menyimpan konfigurasi.

![Save Config](/data-management/config-edit/save-config.en-US.png)

## Langkah 4: Restart Layanan

Pada langkah-langkah di atas, kita telah selesai mengedit file konfigurasi. Selanjutnya, kita perlu me-restart layanan. Cari bagian `Instruksi` dan klik tombol `Restart` untuk me-restart layanan agar file konfigurasi berlaku.

![Restart Service](/data-management/config-edit/restart-service.en-US.png)

[Setelah mengikat domain ke layanan NGINX](/deploy/networking/public-networking), Anda dapat mengakses layanan Vaultwarden melalui domain tersebut.

![Access Vaultwarden](/data-management/config-edit/vultwarden-service.en-US.png)

## Menentukan File Konfigurasi Sebelumnya di Template YAML

Anda dapat menggunakan `configs` di "Service Specification" untuk menentukan file konfigurasi layanan ini sejak awal. Untuk informasi lebih lanjut, lihat artikel [Buat Template dari YAML](/template/template-format).
